# EV Command

EV Command is a mobile-first, single-owner EV charging ledger. It tracks charging sessions, provider costs, daily free-energy allowances, savings, subscriptions, monthly spend, and vehicle running-cost assumptions.

Supabase is the canonical data store. The browser keeps an IndexedDB snapshot and a bounded mutation outbox so the installed app remains useful offline; queued changes are retried when connectivity returns. There is intentionally no separate local-only mode.

## Stack

- React 19, TypeScript, React Router, and Vite
- Supabase Auth, Postgres, Realtime, and private Storage
- IndexedDB offline cache/outbox
- Vitest with V8 coverage and Playwright for Chromium/WebKit smoke tests
- Workbox service worker generated by `vite-plugin-pwa`

## Development

Requirements: Node.js 24+, npm 11+, and access to a Supabase project.

```bash
npm ci
cp .env.example .env.local
npm run dev
```

The required public browser configuration is:

```dotenv
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=your-publishable-anon-key
```

The anon key is expected to be public. Data protection comes from a signed-in Auth session and owner-only row-level-security policies, not from hiding that key.

## Supabase setup

1. In Supabase Auth, create or invite the permanent owner user before applying migration `005_single_owner_auth.sql`.
2. Link the local project and apply the migrations:

```bash
npx supabase link --project-ref YOUR_PROJECT_REF
npx supabase db push
```

3. Confirm `public.app_settings.owner_id` is the intended Auth user UUID. Migration 005 selects the oldest existing Auth user. If no Auth user existed when it ran, bind the owner once in the SQL editor:

```sql
insert into public.app_settings (id, owner_id)
values (1, 'OWNER_AUTH_USER_UUID')
on conflict (id) do update set owner_id = excluded.owner_id;
```

4. In Auth URL Configuration, set the deployed site URL and add the exact local/deployed redirect URLs used by recovery magic-link sign-in.
5. Deploy the new frontend immediately after the RLS migration; the previous anonymous client will correctly lose access.

The owner can set or change a password in Settings. Password sign-in is the normal path and works with browser password managers; magic-link sign-in remains available for first-time setup and recovery. Public signup stays disabled, so password support does not create a public registration path. Passwords and session tokens are intentionally excluded from app backups.

`vercel.json` provides SPA route fallback, immutable hashed-asset caching, and baseline browser security headers for the existing Vercel deployment path.

Existing remote charging history is not deleted or rewritten by these migrations. Personal history is no longer bundled or seeded from source. See [docs/operations.md](docs/operations.md) for the rollout, rollback, backup, and owner-transfer runbook.

## Architecture

The main flow is:

```text
AuthGate
  -> route-level page chunks
  -> useEv facade
  -> data store
       -> pure savings/analytics engines
       -> IndexedDB snapshot + idempotent outbox
       -> authenticated Supabase repository
            -> providers, charging_sessions, app_settings
            -> private vehicle-photos bucket
```

`src/lib/data.ts` owns optimistic state and sync orchestration. `src/lib/repository.ts` owns paginated remote I/O. `src/lib/cache.ts` owns browser persistence; `backup.ts` and `exports.ts` isolate portable-file behavior. Calculation modules in `src/lib/` remain pure and are covered independently. Classic and Minimal are presentation variants over the same routes, store, and domain models; Minimal CSS is loaded only when selected.

## Data behavior

- Every mutation is first committed atomically to the IndexedDB snapshot and outbox.
- Outbox keys are per entity, so repeated offline edits replace older pending edits rather than growing without bound.
- Supabase reads are paginated in 500-row pages and are refreshed through Realtime, window focus, and online events.
- A one-time migration queues legacy local additions and local preferences before removing obsolete localStorage keys.
- JSON backup v2 includes sessions, providers, appearance, budget, vehicle assumptions, and the private vehicle photo.
- Restore is merge-only: exact ledger duplicates are skipped; destructive replace was removed.
- CSV values beginning with spreadsheet formula characters are neutralized before export.

## Security model

The app is intentionally single-owner. Anonymous table access is revoked; authenticated policies call `is_app_owner()`, and vehicle photos are private objects restricted to the owner UUID path. The confirmed owner can use a stored password or a recovery magic link; password setup requires an existing signed-in session and does not enable signup. Database constraints also reject malformed dates, negative/outlandish numeric values, blank provider names, invalid colors, oversized notes, and empty ledger rows.

This is a personal EV ledger, not a high-sensitivity system. The security work is aimed at preventing casual public access and future unsafe writes without adding enterprise administration or multi-tenant complexity.
